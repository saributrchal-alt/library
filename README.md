# ห้องสมุดวัดพุทธอุทยานนาเทิง

`library.nathoeng.com` เป็นเว็บห้องสมุดแยกโปรเจกต์จากเว็บวัด โดยใช้ทะเบียนสมาชิกและบัตรสมาชิก EAN-13 เดิมของ `watt.nathoeng.com`

## โลโก้ห้องสมุด

ใช้โลโก้จั่วไทยสีทองแบบโปร่งใส พร้อมข้อความ Library of Nathoeng, Sakon Nakhon, Thailand, Since 2026 ที่หัวหน้าค้นหาและหน้าเจ้าหน้าที่ และใช้จั่วไทยเป็น favicon

`npm run build` เตรียมไฟล์หน้าเว็บใน `public/` และส่งภาพจาก `assets/` ไปยัง `media.nathoeng.com` ด้วยตัวอัปโหลดและ environment ฝั่งเซิร์ฟเวอร์ที่มีอยู่แล้ว ไม่ต้องแก้ฐานข้อมูล หากโลโก้ไม่เปลี่ยน build จะนำ URL เดิมจาก `/library-branding.json` มาใช้โดยเทียบ SHA-256 จึงไม่อัปโหลดซ้ำ ภาพและคีย์ไม่ถูกฝังไว้ใน JavaScript ของผู้ใช้

สำหรับตรวจหน้าเว็บในเครื่อง ใช้ `npm run build:local` ซึ่งอ่านภาพในเครื่องโดยไม่อัปโหลด ไฟล์ `public/` เป็นผลลัพธ์ build และไม่เก็บใน git; Vercel Functions ยังใช้ `api/library.js` และ `lib/` ที่ตำแหน่งเดิม

## หน้าเว็บ

- `/` ค้นชื่อเรื่อง ผู้เขียน หมวดหมู่ และเปิดรายละเอียดหนังสือ
- `/admin.html` เจ้าหน้าที่วัด (role `admin`) เพิ่ม/แก้ข้อมูลชื่อเรื่อง รับตัวเล่มเข้า ยืม คืน พักซ่อม สละออก และนำกลับใช้
- ใช้เครื่องยิงบาร์โค้ด USB แบบ keyboard wedge ที่ส่ง Enter หลังสแกนในช่อง ISBN, บัตรสมาชิก หรือรหัสตัวเล่ม
- ISBN ใช้กับข้อมูลชื่อเรื่อง หลายตัวเล่มใช้ ISBN เดียวกันได้ ตัวเล่มแต่ละเล่มใช้รหัสภายใน `NTL-xxxxxxxx` ที่ระบบสร้าง หรือรหัสที่เจ้าหน้าที่กรอก
- กดค้นข้อมูล ISBN เพื่อดึงชื่อ ผู้เขียน และภาพจาก Open Library แล้วตรวจแก้ก่อนบันทึก; สามารถใส่ URL ภาพ HTTPS ด้วยตนเอง

## ตั้งค่าก่อนใช้จริง

1. ใช้ **Supabase project เดียวกับเว็บวัด** และรัน [`schema.sql`](schema.sql) ใน SQL Editor หลังตรวจสอบตารางเดิม/สำรองข้อมูล ตาราง `member_card_numbers` และ `members.membership_status` ต้องมีอยู่แล้วในเว็บวัด
2. ที่ Vercel โปรเจกต์ `library` ตั้ง `SUPABASE_URL`, `SUPABASE_SECRET_KEY` จาก Supabase โปรเจกต์เว็บวัด และ `LIBRARY_SHARED_SECRET` ซึ่งเป็นคีย์ใหม่เฉพาะห้องสมุด ตั้ง `LIBRARY_SHARED_SECRET` ค่าเดียวกันใน Vercel โปรเจกต์เว็บวัดด้วย (ไม่ต้องแก้ `SESSION_SECRET` เดิม)
3. เพิ่ม route `library-session` ใน `api/line-login.js` ของเว็บวัดแล้ว ฟังก์ชันนี้อ่าน cookie login ของเว็บวัด ตรวจสมาชิกในฐานจริง และออกโทเค็นอายุ 3 นาทีเฉพาะห้องสมุด
4. หน้าค้นหาสาธารณะเรียก API ฝั่งเซิร์ฟเวอร์ของห้องสมุด ไม่ต้องใส่ key ใน `config.js` ห้ามใส่ secret/service-role key ในไฟล์เว็บ
5. ตรวจจริงด้วยบัตรผู้ดูแล บัตรสมาชิกทั่วไป ISBN หนึ่งรายการ ตัวเล่มสองเล่ม และขั้นตอนยืมคืน

Admin API จะปิดด้วย `503` จนตั้งค่าฝั่งเซิร์ฟเวอร์ครบ และตรวจสิทธิ์ admin ในฐานสมาชิกทุกครั้งที่เรียกใช้งาน การเปลี่ยนสถานะตัวเล่มและยืมคืนทำใน SQL transaction พร้อมล็อกแถวกันยืมซ้ำ

## อัปเดต 27 กันยายน 2569

รัน `migration-20260927.sql` ใน Supabase SQL Editor **หลัง schema.sql เดิมและก่อนเผยแพร่โค้ดรุ่นนี้** ไม่ต้องรัน schema.sql เดิมซ้ำ เพราะจะเปลี่ยนฟังก์ชันกลับเป็นรุ่นเก่า Migration เพิ่มข้อมูลและสถานะในตารางเดิม ไม่ลบทะเบียนเดิม และสร้าง bucket `library-covers` สำหรับภาพปกสาธารณะ (ไม่มีสิทธิ์อัปโหลดโดยตรงจาก browser)

- หมวดหลัก 000–900 และพระพุทธศาสนา 294.3; หัวข้อย่อยเป็นคำค้นเฉพาะวัด ไม่อ้างว่าเป็นเลขย่อยดิวอี้อย่างเป็นทางการ
- ข้อมูลชื่อเรื่อง: ISBN ผู้เขียน สำนักพิมพ์ ปี/ครั้งที่พิมพ์ ภาษา จำนวนหน้า เลขเรียกหนังสือ คำอธิบาย และปก
- แก้ชื่อเรื่องเดิมได้ด้วยตัวเลือกด้านบน; ISBN ซ้ำจะไม่เขียนทับชื่อเรื่องอื่นโดยอัตโนมัติ
- รับตัวเล่มเพิ่มแยกจากชื่อเรื่อง ทุกเล่มมีรหัส สถานะ ตำแหน่งเก็บ และประวัติ
- ภาพ URL / เลือกไฟล์ / กล้องมือถือ: ย่อเหลือสูงสุด 1,200 px และ JPEG ไม่เกิน 500 KB แล้วส่งผ่านเซิร์ฟเวอร์ไปเก็บบน Hostinger เป็น WebP ใน `media.nathoeng.com/uploads/library/YYYY/MM/` ถ้า URL ต้นทางไม่เปิด CORS ให้บันทึกภาพและเลือกไฟล์แทน ปุ่มกล้องบน desktop อาจเปิดตัวเลือกไฟล์ตามความสามารถของอุปกรณ์
- หน้าค้นหาใช้การ์ดและแบ่งหน้า; กดดูรายละเอียดเต็มพร้อมสถานะตัวเล่มและจองยืม ใช้บัญชีสมาชิกวัดเดิม
- จองรับที่วัดหรือส่ง COD โดยไม่ระบุเวลารับ; ต้องยอมรับเงื่อนไขค่าขนส่งและการคืน
- จองกันตัวเล่มใน transaction พร้อมล็อกแถวชื่อเรื่อง และ unique index กันหลายรายการที่ยังไม่จบในตัวเล่มเดียวกัน
- เจ้าหน้าที่อนุมัติ ระบุกำหนดคืนได้ ส่งมอบที่วัดหรือกรอกบริษัทขนส่ง/เลขพัสดุ/ที่อยู่ส่งคืนก่อนบันทึกจัดส่ง
- สมาชิกกดยืนยันได้รับ แจ้งคืนที่วัดหรือแจ้งเลขพัสดุขากลับ; เจ้าหน้าที่ตรวจรับก่อนคืนตัวเล่มเข้าคลังหรือพักซ่อม
- ประวัติรายการและฉลากพัสดุอยู่ในแท็บคำขอยืม; สมาชิกอ่านได้เฉพาะประวัติรายการตนเอง
- สถานะจัดส่งอัปเดตโดยสมาชิกและเจ้าหน้าที่ ยังไม่ได้เชื่อม API บริษัทขนส่งเพื่อติดตามอัตโนมัติ

### ทดสอบก่อนใช้งานจริง

`node --test` ตรวจ API ด้วย mock: สิทธิ์สมาชิก การยืนยันเงื่อนไข ป้องกันทำงานเจ้าหน้าที่ การเข้าถึงประวัติ และการตรวจภาพ

หลังรัน SQL ใช้หนังสือทดสอบหนึ่งชื่อสองตัวเล่ม ตรวจทั้งรับที่วัดและ COD: จอง → อนุมัติ → ส่งมอบ/จัดส่ง → รับแล้ว → แจ้งส่งคืน → เจ้าหน้าที่รับคืน ตรวจกรณีสองคนจองตัวเล่มสุดท้ายพร้อมกัน และคืนเข้าพักซ่อมด้วย ต้องทดสอบกับ Supabase จริงก่อนประกาศพร้อมใช้จริง

อ้างอิงหมวด: https://www.oclc.org/content/dam/oclc/dewey/resources/summaries/deweysummaries.pdf และ https://www.oclc.org/en/dewey/resources/religion/browser.html

## ตั้งค่าภาพปกบน Nathoeng Media

ใน Vercel โปรเจกต์ library ตั้ง Environment Variables สำหรับ Production:

- `MEDIA_UPLOAD_URL=https://media.nathoeng.com/upload.php`
- `MEDIA_UPLOAD_KEY` ใช้ค่าเดียวกับ `upload_key` ใน Hostinger `config.php` (อย่างน้อย 32 ตัวอักษร)

Redeploy หลังตั้งค่า เก็บคีย์เฉพาะฝั่งเซิร์ฟเวอร์ ไม่ใส่ใน config.js หรือ GitHub ไม่ต้องรัน SQL เพิ่มสำหรับการเปลี่ยนพื้นที่เก็บภาพ รูปเก่าและ URL เดิมยังแสดงได้ การแก้ข้อมูลหนังสือโดยไม่เปลี่ยนภาพจะไม่อัปโหลดภาพเดิมซ้ำ หาก Hostinger ขัดข้องจะรายงานข้อผิดพลาดและไม่ส่งภาพใหม่ไป Supabase
